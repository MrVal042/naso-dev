# Benchmarks: what an agent loads at session start

Every token in `AGENTS.md`, `CLAUDE.md` and the files they import is read at the start of
every session, before the agent does any work. This page is the baseline every change to
what NASO writes is measured against. A change that makes the briefing longer has to say
what it buys; a change that makes it shorter has to show the number went down.

## Method

- `npx naso-dev stats <repo> --json`, which counts CLAUDE.md and every file it imports,
  AGENTS.md, and the NOW section of the handoff, each file once.
- Tokens are characters divided by four, rounded up. No tokenizer: the same number on every
  machine, wrong by about the same factor for every file, which is what a before/after
  comparison needs. Real tokenizers give a different absolute number; the ratios hold.
- Each public repository was cloned with `--depth 50` at the commit below, and set up with
  NASO 1.5.4: `npx naso-dev@1.5.4 <repo> --yes --no-hook`. That writes `AGENTS.md` and a
  one-line `CLAUDE.md` link and needs no network.
- "As cloned" is what the repository itself shipped for agents before NASO. None of the
  seven sample repositories shipped an AGENTS.md or a CLAUDE.md.
- The field repository is a private application this tool is used on daily. It is not
  named. It was measured twice: as generated by 1.5.4 in a scratch clone, and as it is
  committed after people and the `review` prompt corrected the block.

The median generated load is **1,670 tokens**. The reviewed field briefing is **2.9 times**
its generated size.

## Largest sections

As generated, the same two sections lead almost every repository, and they say nearly the
same thing everywhere:

| Section | Tokens, every sample | Share of the median load |
| --- | ---: | ---: |
| Decisions | 284–288 | 17% |
| Scope | 224–226 | 13% |
| CLAUDE.md link | 34 | 2% |

The rest is the per-repository content: the title paragraph (173–378), Project Structure
(200–270), Commit Standard (about 170–205), and in gson a Merge Request Checklist (290).

As reviewed, the field repository's largest sections are Commands (815), Stack Rules (780),
Project Structure (436), Decisions (302) and Deploy and CI (293).

## What this means for the later phases

- About 540 tokens of every generated load (Decisions, Scope, the CLAUDE.md link) is the
  same text in every repository. That is the first thing to move into a file read on
  demand.
- Generation is not where the size comes from in practice. The review step roughly triples
  the block, mostly by adding commands, stack rules and project structure an agent needs.
  The layered layout has to give that added detail somewhere to go other than the root
  block, or the root grows back after every review.
- No sample repository shipped any agent file, so for most teams NASO's load is the whole
  load. It should stay well under the reviewed field size.

## Reproduce

```bash
git clone --depth 50 https://github.com/spf13/cobra.git && cd cobra
npx naso-dev@1.5.4 . --yes --no-hook
npx naso-dev stats . --json
```

Each later phase adds its own row set below, with the same repositories at the same
commits, and the change against this baseline.
