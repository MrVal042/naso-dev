# Changelog

## 2.0.2

### Fixed

- **Branch templates read ticket keys as keys.** In `<type>/<JIRA-KEY>-<short-name>`, every placeholder used to match anything, so `local/preview-1121-0104` was reported as following the rule. A ticket placeholder (`<KEY>`, `<JIRA-KEY>`, `<ticket>`, `<issue>`) now matches an uppercase key (`SCRUM-142`, or `SCRUM` before a `<n>`), and `<n>` matches digits. The review prompt and the pre-commit branch warning both use it.
- **`hotfix/vX.Y.Z` is not a missing path.** A version template (`vX.Y.Z`, `x.y`) is never checked on disk, and neither is an example branch name such as `feat/SCRUM-12-login` when no `feat/` folder exists.
- **Guides only this machine has are named.** When AGENTS.md is not ignored but the guides its block links are (`.naso/` in `.git/info/exclude`), `briefing` prints a notice and the review prompt says the block reaches every clone and the guides reach none. `briefing migrate` warns before moving text there.
- **Commands the pinned version lacks.** When the block runs a command (`handoff`, `lesson`, `agents`, …) that package.json's naso-dev predates, the version note says which, the version that added it, and the install line that pins one that has it.
- **`refresh` says only what it did.** It reported noting the refresh on the "Generated by" line even when a reviewed block had reworded that line and nothing changed; now it says only the stamp moved.
- **Owner patterns past the first five keep their lines:** "lines 10-13 and 1 more (line 14)", not "lines 10-13 and 1 more".
- **Pointer files pass Prettier, and stay out of git from a worktree.** The pointers for Cursor, Copilot, Gemini and Windsurf, and the CLAUDE.md link, now have the blank lines Prettier writes around the naso markers and after front matter. In a linked worktree, created pointers were written to `.git/worktrees/<name>/info/exclude`, which git never reads, so they showed as untracked; the exclude now goes to the common `.git/info/exclude`.
- **The review prompt defers to the repository.** It asks for Decided rows to be proposed unless the repository's decisions folder or guide says rules already in its docs are not proposed again, and counts repeating CLAUDE.md, which every Claude Code session loads, as a reason to cut a line.

### Changed

- **Every setup question defaults to Yes, marked (recommended).** Enter now commits AGENTS.md and `.naso/`, chains a hook NASO did not write, installs into a tracked `core.hooksPath`, regenerates an untouched NASO block, points the agents this repository uses (or all four) at AGENTS.md, and adds the Claude Code hooks and skills. Claude Code deny rules default to `NASO_SCOPE` when it is set and stay No otherwise, because which CODEOWNERS owner you are cannot be guessed. The plan is still shown and accepted before anything is written, and `--yes` asks nothing, so scripted runs keep their defaults.
- The examples and the demo are regenerated with 2.0.2.

Copilot's instruction files (`.github/copilot-instructions.md`, `.github/instructions/`) are a briefing, like AGENTS.md, and never count toward an area. A `.github/` that holds anything else is still one.

The examples and the demo are regenerated with 2.0.1.

## 2.0.0

### Breaking

- **The NASO block is layered: a root every session reads, and guides read when a task needs one.** The block keeps what every session needs (what the repository is, Read First, the rules that are easy to get wrong, the areas, secrets, the validation commands, when the work is done) and a **When You Touch** table that names a guide in `.naso/guides/` for each kind of task: `conventions.md` (Code Conventions, Stack Rules, Boundaries), `workflow.md` (Scope, Commit Standard, Merge Request Checklist), `decisions.md` (Decisions), and one per area whose folders a doc describes (its Source Map or Feature To Folder Map). A guide with nothing to say is not written and gets no row. Anything that reads those sections from `AGENTS.md` alone, or edits them there, now finds them in the guide the table names.
- **`briefing` checks the guides with the block.** Every guide the block links is read, and its paths, quotes, citations and claims are checked as if they were in the block. A linked guide that is not on disk is MISSING, even where `.naso/` is git-ignored, because the block sends the agent to it. A block from before 2.0.0 still passes, with a notice that names the sections loading in every session and the command that splits them.
- **Area lines carry no file count, and the root files are not listed.** "`docs/` — documentation; 10 files" went stale with every commit and no agent used it; `ls` gives both fresh. The line keeps what `ls` cannot say: the area's role, its manifest and its entry point, and the root keeps the entry-point sentence.
- **Which Document Wins is a heading only when the repository has lines to quote.** With none, its one sentence opens When This Block Is Wrong.

### Added

- **`naso-dev briefing migrate`** shows how a block from before 2.0.0 splits into guides, and `--write` does it: each section moves word for word with every line people wrote in it and its sub-sections, the table is added before Project Structure, and NASO's own two Read First lines that named sections in the block are updated. A section whose heading NASO does not know stays in the block and is named. A guide already on disk is never replaced; the run stops and writes nothing. An untouched block keeps reading as untouched; a reviewed one keeps reading as reviewed, and its guides carry no digest, so nothing regenerates over them. `review` tells the agent to migrate before anything else.
- **Guides are edited like the block.** Each carries a digest. `--force` keeps a guide people changed, and `--discard-edits` replaces it after saving it under `.naso/backups/`. `decide` and `decisions sync` keep the line saying where the list is current in the decisions guide, and that is not counted as an edit.
- **The block has a budget.** `briefing` gives a notice when the block passes 60 lines of text, saying to move detail into the guide the table names for it. `review` asks the agent to keep it under that.
- **`stats` lists the guides apart**, with their size, as read when a task needs one; they are not counted in the session-start total. `--json` has them as `onDemand`.
- **Setup's plan lists every guide** with its line count, before anything is written. `guide <area>` points to the area's guide, and `guide --tour` walks the guides' sections with the block's.

- **Pointers for other agents: Cursor, Copilot, Gemini and Windsurf.** `naso-dev agents <name…|all>`, or `--agents` at setup, writes one line in each agent's own file that sends it to AGENTS.md, never a copy: `.cursor/rules/naso.mdc` and `.windsurf/rules/naso.md` as rules applied to every request, `.github/copilot-instructions.md`, and `GEMINI.md` with Gemini CLI's own `@AGENTS.md` import. Codex reads AGENTS.md itself and gets nothing. A file a person keeps is appended to inside naso markers; one that already names AGENTS.md (or a `.cursorrules`, another rule file, or `.gemini/settings.json` that does) is left alone; one git tracks is left alone in a local run, with the line to add. A file it creates in a local run is kept out of git. In a terminal setup asks, No by default, and offers the agents the repository is set up for first; with `--yes` and no `--agents` it writes none and names each agent it detected with the flag that would point it. `naso-dev agents` with no name says which agents a repository uses and whether each loads AGENTS.md. Each pointer is 34–57 tokens, loaded only by its own agent.
- **`naso-dev workspace`** for a folder that holds several repositories and is not one itself. It finds them two levels down (a `.git` folder, or a `.git` file in a linked worktree; hidden and dependency folders are skipped), runs no git command in the folder, changes nothing inside a repository, and shows its plan before writing: an AGENTS.md block with one row per repository (its briefing, its default owners from CODEOWNERS, and what this machine may write in it, from its `.naso/config.json` or `--read-only`; a column no repository has a source for is left out), the CLAUDE.md link, a shared handoff in `.naso/HANDOFF.md` for state that spans repositories, and `.naso/config.json`. `--read-only` is remembered. A block people edited is kept unless `--force`, which saves it under `.naso/backups/` first. Run again, it adds new repositories, and with nothing new it writes nothing. The handoff commands resolve to the folder even when it sits inside another git repository.

### Fixed

- **`npm test` counts as running the test script.** A CI job that ran `npm test` (or `npm t`, `npm start`, or `pnpm lint` and `yarn lint` without `run`) had the briefing say "Declared but not run by CI: `npm run test`". `pnpm` and `yarn` count only for a script package.json declares, so `pnpm install` is still pnpm's own; `bun test` is bun's own test runner and is not the script.

### Documentation

- **A README that fits on one screen**: what NASO does in one line, badges, a demo recorded from a real run (`docs/demo/setup.svg`, re-recorded by `node docs/demo/record.mjs`), a three-command quick start, the agents it works with, and the token numbers. The full reference moved to `docs/reference.md`, word for word.
- **`examples/`**: an Expo app, a NestJS API, a Python service, a Go CLI, a Rust library, a Terraform module and a pnpm monorepo, each with what NASO wrote for it (644–966 tokens at session start). `node examples/build.mjs` regenerates them from the real setup.
- **`docs/comparison.md`**: NASO beside a hand-written AGENTS.md, Claude Code's `/init`, rule-sync tools and repository packers, including where NASO is weaker.
- **`docs/good-first-issues.md`**, issue and pull request templates, and launch drafts in `docs/launch/` (not posted).

### Changed

- **The review prompt is shorter** (its fixed text is 19% smaller), covers the guides, and asks for the block to stay under 60 lines.
- **What an agent loads at session start halves.** Same repositories, same commits (`docs/benchmarks.md`): the median of seven goes from 1,670 tokens (1.5.4) and 1,812 (1.6.0) to 849, 49% below 1.5.4. The field repository's generated briefing goes from 2,115 to 1,214, and its reviewed briefing, migrated, from 4,583 to 1,335. The guides add nothing until a task needs one.

## 1.6.0

### Added

- **A handoff between sessions, bounded.** Two parts, kept differently. NOW is one current state that `naso-dev handoff set` replaces whole (from an argument, `--file`, or stdin): where things stand, the next steps, the open items. `- [ ] …` and `- Waiting on <who>: …` lines get an id and never age out. A `set` that leaves one out carries it over into the new NOW and prints "carried over: (n) …", because an agent rewriting NOW drops a waiting line by mistake far more often than it means to close one; only `handoff done <id>` or `handoff set --close <id,…>` closes one, and the log records it. A line written with an open item's id updates that item instead of adding a second. `handoff log "…"` adds dated history below NOW, and only the log ages out: past 14 days or 60 lines, oldest first, into `handoff-archive/YYYY-MM.md`, which nothing reads at session start. `handoff add` still works, as `log`, with a one-line notice. A Decisions this week section links the records dated in the last seven days and never copies them. With `--track` the handoff is `.naso/HANDOFF.md`; kept local, it is `<git common dir>/naso/HANDOFF.md`, so every linked worktree reads and writes the same one. Setup writes it (it is in the plan, and an existing one is never replaced), and the pre-commit gate warns, never blocks, when NOW is over 60 lines.
- **The briefing starts with Read First:** the handoff's NOW section, then the briefing, then the decisions for the paths being changed, and when to `set` NOW and `log` a line. With the lessons line it costs 141–146 tokens per repository (median load 1,670 → 1,812 with Phase 2; `docs/benchmarks.md`). A block written before this release still passes `briefing check`, with a notice ("Read First missing (added in 1.6.0)"), and `review` gives the agent the section as NASO would write it today, to add inside the markers, and says to create the handoff first when the section would cite a file that does not exist yet.
- **Rules That Are Easy To Get Wrong.** A section near the top of the block, at most ten lines, each a rule with its reason and its source, from files the repository already has: accepted decisions that state a constraint (at most four; a decision says never, always, must, only, do not, instead of, rather than or should not, so "change the schema only through migrations" is a rule and "three plans cost 10, 20 and 30 dollars" is not; those whose record says which paths they apply to come first, then the newest, each cut to its first sentence and its first reason), committed env templates (placeholders only, because every clone gets them), CODEOWNERS (patterns grouped by owner, with line numbers, the catch-all owner, and patterns that match no tracked file), commitlint and what enforces it (a commit-msg hook, CI, or nothing), the documented branch pattern, and CONTRIBUTING's own lines on one ticket per pull request, merge mode, approval and exceptions, quoted as written with their line, so the checker tests them, and with no reason added: a guide line rarely gives one, and NASO does not make one up. A repository with none of these gets no section.
- **Each of those is said once.** The branch pattern and CONTRIBUTING's merge rules moved out of Commit Standard, and the **Owners.** line out of Boundaries, into the new section with their reasons. psf/requests, which has CODEOWNERS and nothing else, gains the section and its load still grows by only 33 tokens.
- **Lessons.** `naso-dev lesson --title … --why … --apply … [--type feedback|project|reference]` writes one file per lesson with front matter and **Why:** and **How to apply:** lines, and one line in a lessons index. Read First links the index, never the lessons, and says to record a lesson when a person corrects the agent or confirms an approach. `naso-dev lessons` prints the index; `lessons audit` reports a lesson whose cited path is gone (error), and lessons that duplicate or contradict each other (warnings), and changes nothing. Lessons sit beside the handoff: `.naso/lessons/` with `--track`, the git common directory otherwise.
- **A block from before 1.6.0 is told about the rules section too.** `briefing check` notices a missing Rules That Are Easy To Get Wrong only when the repository has rules to state, and `review` gives the section to add right after When This Block Is Wrong.
- **Claude Code extras, all opt-in: deny rules, hooks and skills.** `naso-dev claude --deny` writes `permissions.deny` Edit rules for every path outside your CODEOWNERS ownership (`--owners`), or outside `NASO_SCOPE`, so an edit outside scope never happens instead of being caught at commit. They go to `.claude/settings.local.json`, kept out of git, because which owners "we" are is per person and a shared file would deny the same paths to every teammate. CODEOWNERS is read the way the hosts read it: gitignore semantics, a wildcard last segment (`docs/*`) matching files rather than folders as GitHub documents, last match wins, a line with no owners making its paths nobody's, GitLab sections evaluated separately with their default owners. A pattern that cannot be translated exactly (`!`, `[ ]`, `\`) is reported by line and denies nothing it might match. A folder becomes one rule only when nothing under it could ever be yours; otherwise its tracked files are denied one by one and the output says new files there are not. NASO's own files are never denied. `--hooks` adds a SessionStart hook that prints the handoff's NOW and the briefing check, and a Stop hook that reminds the agent once to update the handoff when files changed and it did not; both run the vendored `.naso/tooling/session-hook.mjs` in exec form (no shell, the same on every platform), have an 8-second limit and always exit 0, and `--hooks` refuses while the vendored toolset lacks the script. `--skills` writes `naso-handoff`, `naso-pre-pr` (a self-review for security, concurrency, docs and the failure path of every network, disk, database and subprocess call, in words that suit any language, then `git ls-remote` to check the push landed), `naso-decide` and `naso-sweep`. The person's own settings, rules, hooks and skills are kept in order; NASO removes only rules it recorded as its own, and never replaces a skill without its marker. Setup asks about each (default No), or takes `--claude-deny --owners …`, `--claude-hooks`, `--claude-skills`; `doctor` reports drift between ownership and the deny rules, and hooks whose script is gone. Deny rules cover Claude Code's file tools and the shell commands it recognises, not a script that writes files itself.
- **`stats` counts project skills** by their front matter, which Claude Code loads at session start; the body loads only when a skill is used.
- **`naso-dev stats` measures what an agent reads before it starts.** It estimates the tokens (characters divided by four, no tokenizer) of `CLAUDE.md` and every file it imports, `AGENTS.md`, and the NOW section of the handoff, counts each file once however many routes reach it, and ranks the largest sections. Imports are followed the way Claude Code follows them: from the importing file, five hops deep, never inside code spans or code blocks, and never outside the repository; an `@/` alias or an `@name` mention in prose is not reported as a missing file. `--json` prints the same numbers. It needs no git repository and no manifest.
- **`docs/benchmarks.md` is the baseline.** NASO 1.5.4 on six public repositories across Node, Python, Go, Rust, Java and Terraform, on itself, and on a field repository before and after review. The median generated load is 1,670 tokens; the reviewed field briefing is 4,583. Every later change to what NASO writes reports against these numbers.
- **The test suite runs every phase against a fixture matrix** (`test/fixtures/matrix.mjs`): a Node monorepo, Python, Go, Rust, Java/Gradle, Terraform only, docs only, a repository with no commits, a linked worktree, GitLab sectioned CODEOWNERS, a husky hook, and a plain folder holding two repositories. Each is generated by the test that uses it.
- **CI runs the tests** on Ubuntu, macOS and Windows with Node 20 and 22.

### Fixed

- **Package managers run on Windows, safely.** npm, npx, pnpm, yarn and bun are `.cmd` files there. Node 18.20.2, 20.12.2, 21.7.3 and every later version refuse to spawn a `.cmd` or `.bat` without a shell (EINVAL), after CVE-2024-27980 ("BatBadBut"), so `--save-dev` and the gate's Format and Lint steps could not start on Windows. Quoting the arguments is not enough there, because cmd.exe still reads `%`, `^`, `&`, `|`, `<`, `>`, `( )` and quotes as syntax. Commands are now looked up on `Path` in `PATHEXT` order. An `.exe` runs directly, with no shell. A `.cmd` or `.bat` runs as `%ComSpec% /d /s /c "<line>"` with `windowsVerbatimArguments`, escaped the way cross-spawn escapes: each argument quoted for the program's own parser, then every cmd.exe metacharacter, quotes included, escaped with `^`. Shims that pass `%*` on to node, so cmd.exe parses the line a second time, are escaped twice: the npm, npx, pnpm, pnpx, yarn, yarnpkg, bun, bunx and corepack `.cmd` files and every `node_modules\.bin\*.cmd`. Any other `.cmd` or `.bat` is escaped once, as cross-spawn does. Tests cover arguments and paths with spaces, `&`, `|`, `<>`, `%`, `^`, `"`, `( )`, `!`, `;`, `,`, `*?` and trailing backslashes, and on Windows a real `npm.cmd`-style shim in a folder named `odd & dir (1)` must receive every one of them unchanged, while hostile arguments to a plain `.cmd` must not run anything. CI also packs the tarball with the real `npm` and runs it with the real `npx` (`npx --package <tarball> naso-dev --dry-run`), from folders named `pkg & (1)` and `repo & (1)`, on every OS.
- **The test suite no longer needs a POSIX shell.** Fake package managers are a Node script with an `sh` and a `.cmd` shim, copies use Node's `fs.cp`, and the two tests that need `chmod` to make a directory read-only say why they skip on Windows. CI checks out with `core.autocrlf false`.

## 1.5.4

### Fixed

- **A directory passed as a value no longer becomes the repository.** `decide --applies supabase/migrations/` printed `pnpm dlx naso-dev decisions accept` while every other decide in the same repository printed `pnpm exec`: the bin read the `--applies` directory as the target, found no package.json there, and spelled the command for a repository without naso-dev. The target is now the last positional argument as the commands themselves parse it.
- **A quote is checked against the citation next to it.** The checker paired each “…” with the citation whose start was nearest, so a citation closing the previous sentence beat the one right after the quote, and a correct quote was reported WRONG. It now measures the text between them, and a tie goes to the citation after the quote.
- **Import-alias prefixes are not path claims.** "`@/` resolves to the repository root" was reported as MISSING: @/. Tokens starting `@/`, `~/` or `#/` are skipped.
- **A `packageManager` field the lockfiles contradict loses.** A pnpm pin with no `pnpm-lock.yaml` over a maintained `package-lock.json` made the briefing say pnpm while every doc said npm. The lockfile now wins, and the Package manager line says why.
- **The Scope section says which hook steps run.** It said the hook checks "format and lint" in a repository with no Prettier config and no ESLint, where both steps skip. It now names the steps that run and why the others skip.
- **`validate` no longer type-checks twice.** With `"lint": "tsc --noEmit"` and no `typecheck` script, the full run ran tsc as Lint and again as TypeScript. The second run is skipped and says why.
- **Area counts leave out decision records.** "`docs/` — documentation; 10 files" went stale with the first `decide`. The count excludes the decisions folder and says so.
- **A TypeScript range is stated as a range.** `~5.8.2` was rendered "TypeScript 5.8.2" with 5.8.3 installed.
- **An alias to the repository root says so.** tsconfig `"@/*": ["./*"]` was rendered "@ → *". It is now "@ → the repository root".
- **The never-exit line agrees in number.** "`pnpm run dev` never exit …; do not run them as checks" now reads "never exits …; do not run it as a check" for one script.

## 1.5.3

### Fixed

- **A fresh clone gets one instruction for the hook.** The block said a clone has no hook "until setup runs there", while the toolset README said refresh reinstalls it. The block, the toolset README and `doctor` (when the hook is missing) now all name `npx naso-dev refresh`, which installs the hook and, at the version already vendored, changes nothing else.
- **The block drops lines that do not change what an agent does.** Agents removed all of these in both field repositories: "Local excludes" (one machine's `.git/info/exclude`), "Ignored paths" and "Re-included" (a restatement of `.gitignore`), the "Language mix" counts, and a second "Import aliases" line under Boundaries (the mapping is stated once, under Code Conventions, with the files that declare it). Ignored paths that carry a rule stay: credentials, generated files, and files the repository says are not edited by hand. The Feature To Folder Map lists only folders whose name says what they hold, without file counts, and is left out when none does.
- **The vendored files no longer make the repository's own lint warn.** Every vendored script starts with `/* eslint-disable */`, and ESLint 9 reports an unused disable directive by default, so `eslint .` warned about `.naso/tooling/` (3 warnings in the field). Setup added `.naso/` to `.prettierignore` but never to ESLint. It now adds `{ ignores: ['.naso/'] }` as the first entry of a flat config's exported array (plain array, `defineConfig`, `tseslint.config`, or a named array), in the config's own quote style and indent, or `.naso/` to `.eslintignore` for a legacy config. A config it cannot place the line in is left alone and the plan says what to add. `--no-ignore-files` opts out of every ignore edit: `.prettierignore`, `.dockerignore` and ESLint.
- **`doctor` runs the repository's ESLint on `.naso/`.** With an ESLint config and `node_modules/eslint` installed, it reports anything ESLint prints for the vendored files, with the fix.
- **`.naso/config.json` no longer reads as the current version.** Its `"version"` stayed at the setup version after every refresh, by design, and two separate reviews reported it as a mismatch with the toolset. Setup now writes `setupVersion`; a config with `"version"` is still read. `doctor` prints "setup ran with X (refresh never rewrites it)".
- **A curly-quoted citation is checked against the lines it cites.** Only citations past the end of a file were reported; one inside the file could point at the wrong sentence, or misquote it, and pass. When the block quotes text in “…” next to a `` `file` line N `` or `lines N–M` citation, `briefing` now looks for the quote in those lines (whitespace, list markers and Markdown emphasis normalised) and reports a mismatch as WRONG, with the file, the line and the first differing word.
- **The version notes say which version to run.** "Run `npx naso-dev refresh` with the version the team uses" left the reader to guess. `briefing`, `review` and `refresh` now read the exact devDependency and lockfile version: a toolset behind the pin gets `npx naso-dev@<pinned> refresh`; a toolset ahead of it gets the exact install of the toolset's version, since refresh refuses to move it back. Without a pin, the note names the running version's own refresh. `doctor` prints the same advice on a "naso-dev in package.json" row.
- **`review` asks for a full review while the block is uncommitted.** It told a second review to diff from the last commit that touched AGENTS.md; with the block added but not committed, that commit predates NASO and the diff was the repository's whole history (184 files in the field). When HEAD's AGENTS.md has no `naso:start` marker, it now says the block is uncommitted and asks for the whole block to be reviewed.
- **`review` no longer proposes decisions that are already recorded.** A Decided row counted as recorded only when a record's source named its exact line, so records citing "docs/architecture.md section 2" matched nothing and 9 of the 10 rows listed in the field were already recorded. A row now counts as cited when a record's source names its file and its line, a line range or a section heading that holds it, or the record states the same decision.
- **A Decided row that names another owner is listed apart.** "Decided (customer-api)" belongs to another repository; `review` lists it as decided elsewhere, not as a decision to propose here.
- **`decide` warns when the line it cites is already cited.** Another record citing the same line, by number, range or section, is named, with how to supersede it. A source that names a file without a line gets a note asking for "<file> line <n>".
- **`review` no longer lists proposed decisions as the repository's own rules.** Its "own rules" list matched every Markdown file under `docs/`, so the agent's unaccepted proposals in `docs/decisions/` were named as the authority it checked itself against. The decisions folder is left out; accepted records are listed under "Decisions a person accepted".
- **`decide` no longer cuts a file name mid-word.** Names were cut at 50 characters ("…-no-ve.md", "…-with-react-ho.md"). They are now cut at the last hyphen before 50.
- **`refresh` and `briefing refresh` say what they changed.** They printed "No prose touched" and "Briefing content untouched", but since 1.5.2 they also note the refresh on the "Generated by" line. They now say so.

### Added

- **Setup derives the toolchain facts agents had to add by hand.** Each is read from the file that states it, without running it, and cited:
  - **Prettier options** (`.prettierrc`, `prettier.config.*` or package.json `"prettier"`): quotes, trailing commas, width and the other layout options, on the Format line.
  - **Jest preset, module mocks and setup files** (package.json `"jest"` or `jest.config.*`), on their own line under Code Conventions.
  - **Expo runtime version policy and experiments** (`app.config.*` or `app.json`): what the policy asks when native code changes ("bump `version`"), and what `typedRoutes` and `reactCompiler` change, under Stack Rules.
  - **Metro transformers** (`metro.config.*`): an SVG transformer means an `.svg` import is a component, not an image source.
  - **Merge request checklist items** (`.gitlab/merge_request_templates/*.md`, `.github/pull_request_template.md`), quoted with file and line in a new Merge Request Checklist section.
  - **Merge mode, approval rules and commit-rule exceptions** from CONTRIBUTING ("Revert messages are accepted", squash, fast-forward, code owners who may self-approve), quoted under Commit Standard.
